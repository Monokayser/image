# Member Slides Presentation Script

## Slide 1: Member 1 - Project Manager + GitHub Maintainer

### On-slide summary
- Created the GitHub repository and project structure
- Managed branches for team collaboration
- Reviewed and merged code
- Tracked team tasks and progress
- Prepared the final repository for submission

### Speaker notes
Member 1 worked as the project manager and GitHub maintainer.  
This role was responsible for creating the repository, organizing the main folder structure, and making sure all team members could work in parallel without conflicts.  
They managed the branches, reviewed pull requests, merged finished work, and kept track of which task was assigned to each member.  
At the end of development, Member 1 also prepared the final repository structure so the project was clean, complete, and ready for submission and presentation.

## Slide 2: Member 2 - Backend Developer

### On-slide summary
- Developed the Spring Boot backend
- Created authentication, workspace, task, and comment APIs
- Connected PostgreSQL database
- Implemented CRUD logic and validation
- Tested backend workflows

### Speaker notes
Member 2 was responsible for backend development.  
This included setting up the Spring Boot application, connecting the PostgreSQL database, and implementing the main API routes for authentication, workspaces, tasks, and comments.  
They also handled the CRUD operations, input validation, and access control for secured routes.  
Finally, the backend developer tested the API workflows to make sure registration, login, workspace creation, task management, and comments worked correctly.

## Slide 3: Member 3 - Frontend Developer

### On-slide summary
- Built the React frontend with TypeScript
- Created login, register, workspace, and task board pages
- Connected frontend with backend APIs
- Improved layout, usability, and demo readiness

### Speaker notes
Member 3 handled the frontend development of the project.  
This included building the user interface using React and TypeScript, creating the login and registration forms, workspace management page, and task board page.  
They connected the frontend to the backend APIs so that user actions could trigger real operations such as logging in, creating workspaces, and managing tasks.  
They also improved the overall user experience and made the interface ready for live demonstration.

## Slide 4: Member 4 - DevOps / Docker / CI-CD

### On-slide summary
- Wrote the Dockerfile
- Added docker-compose for local execution
- Set up GitHub Actions workflows
- Ensured the app builds and tests automatically
- Prepared Docker image publishing

### Speaker notes
Member 4 worked on DevOps, Docker, and CI/CD.  
This role created the Dockerfile to package the application and wrote docker-compose to run the app together with PostgreSQL in a local environment.  
They also set up GitHub Actions workflows to automatically run frontend and backend checks whenever code was pushed.  
In addition, they prepared Docker image publishing so the project could be built and deployed more easily in the future.

## Closing Statement

This project was completed through clear teamwork, where each member had a defined responsibility.  
By combining project management, backend development, frontend development, and DevOps practices, the team successfully delivered a complete full-stack Task Management System.
